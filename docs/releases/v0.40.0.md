## What's New in v0.40.0

v0.40.0 is the **wiki-write confirmation release**. Every `POST /page` to an
existing page now goes through a one-shot 8-char confirmation token (TTL 300s)
instead of silently overwriting. Companion commits unify WebUI dialogs on the
Radix Dialog primitive and extract a handful of duplicated background-task
helpers.

**Before** (v0.38.0 era):

```bash
# POST /page to an existing page — silent overwrite
curl -X POST /api/wiki/{wiki_id}/page -d '{"page_name":"x","content":"new"}'
# → 200 OK (no confirmation), last-writer-wins
```

```python

# duplicated between start_auto_compact and start_confirmations_cleanup
```


Highlights:

- **POST `/page` token-confirmation flow** — wiki-bound, page-bound,
  one-shot consumption. Confirmation tokens leak the wiki's intent to
  overwrite until either a retry-with-token succeeds, the user gives
  up, or the cleanup task reaps them after 5 minutes.
- **Background token cleanup** — `MemoryConfig.confirmations_cleanup`
  section drives `AgentService.start_confirmations_cleanup`. Pairs with
  the existing auto_compact via shared `_run_periodic_loop` helper.
- **Two transports with explicit priority** — query string (PRIMARY,
  legacy v0.40 callers) wins on disagreement; body (back-compat).
  INFO log emits token-length only, **never** values.
- **WebUI modal unification on Radix Dialog** — 9 modals across the
  app now ship Escape + focus trap + ARIA consistently; 2 broken
  modals (WikiDreamProposals, WikiManager) fixed without anyone noticing.
- **Backend helper consolidation** — `make_confirmation_id`,
  `get_confirmation_with_decoded_args`, `_run_periodic_loop`,
  `_feature_running` each become the single source of truth for one
  formerly-duplicated pattern.

## Before / After

### Confirmation flow

```python
# Before — bypass for fresh-install scrub, but no token concept
def write_page(wiki, page_name, content):
    return wiki.write_page(page_name, content)  # last-writer-wins
```

```python
# After (interfaces/server/http/wiki/_wiki_ops.py:write_page)
if page_exists and not confirm_token:
    if not db or not wiki_id:
        raise HTTPException(status_code=503, ...)
    confirmation_id = WikiDatabase.make_confirmation_id()
    db.save_confirmation({
        "id": confirmation_id,
        "wiki_id": wiki_id,                      # cross-wiki replay blocked
        "tool": "wiki_page_update",
        "arguments": {
            "page_name": page_name,
            "expires_at": time.time() + 300,     # 5-minute TTL
        },
        "action_type": "write",
        "status": "pending",
    })
    raise HTTPException(409, detail={
        "confirmation_id": confirmation_id,
        "existing_page": {"word_count": ..., "content_preview": ...},
    })

if confirm_token:
    if not db: raise HTTPException(503, ...)
    conf = db.get_confirmation_with_decoded_args(confirm_token)
    if not conf or conf.get("status") != "pending":
        raise HTTPException(400, "Invalid or expired confirmation token")
    if wiki_id and conf["wiki_id"] != wiki_id:
        raise HTTPException(400, "Token does not match wiki_id")
    if time.time() > conf["arguments"].get("expires_at", 0):
        raise HTTPException(400, "Confirmation token expired")
    if conf["arguments"].get("page_name") != page_name:
        raise HTTPException(400, "Token does not match page_name")
    db.delete_confirmation(confirm_token)        # one-shot
```

### Transport resolution

```python
# routes.py (default + scoped variants — both updated)
body_token  = body.get("confirm_token")
query_token = request.query_params.get("confirm_token")
if query_token and body_token and query_token != body_token:
    logger.info(
        "wiki_write_page: confirm_token resolved from query string, "
        "overriding body (query_token_len=%d body_token_len=%d)",
        len(query_token), len(body_token),
    )
confirm_token = query_token or body_token   # query > body
```

## Migration

### Automatic
None — `memory_config.json` is auto-merged with defaults on first server
start. New `confirmations_cleanup` section adds `{enabled: true, interval_seconds: 300.0}`.

### Manual (only if upgrading pre-v0.40 wikis)
- Clients calling `POST /page` to existing pages: surface the 409
  `confirmation_id` to the user and re-POST with the token. Otherwise
  every write to an existing page will see "409 Conflict" instead of the
  previous "200 silent-overwrite" — **a behaviour change that is the
  whole point of the release**.
- WebUI callers: bundle hash changed (Editor chunk +33 kB Radix Dialog
  primitives). Hard-refresh once.

## Technical Notes

### Token format & storage
- `confirmation_id`: 8 lowercase hex chars (`uuid.uuid4().hex[:8]` via
  `WikiDatabase.make_confirmation_id`); 16M id space is sufficient
  given 300s TTL + one-shot consumption + 5-minute cleanup.
- Storage: existing `confirmations` table, `arguments` JSON column carries
  `{page_name, expires_at}`. **No schema change**.
- Cross-wiki replay protection: top-level `wiki_id` column.
- One-shot: `db.delete_confirmation(confirm_token)` on success.

### Transport priority rationale
v0.40 had two transports at different times: early v0.40 (commit `380427f`)
issued `?confirm_token=<id>` query string; commit `9092960` moved to body
for HTTP-access-log-leak hygiene. Subsequent v0.40.0 (`652e2bc`) re-introduced
query as primary because several legacy callers still depend on it. New callers
should prefer body; old callers continue to work.

### Periodic-task runner pattern
Two near-identical asyncio sleep-loop bodies (auto_compact +
confirmations_cleanup) consolidated into `AgentService._run_periodic_loop`.
Helper detects sync vs async `tick_fn` via `inspect.iscoroutine(result)` —
works for both `lambda: wiki_db.delete_expired_confirmations()` (sync, returns
int row count) and `lambda: self.auto_compact.check_expired(...)` (sync
returning a coroutine).

### Dialog consolidation
- New `components/wiki/ConfirmDialog.tsx`: title / description /
  confirm-label / cancel-label / destructive / onConfirm / onCancel.
- New `components/wiki/PageExistsDialog.tsx`: 409-specific with
  pageName + wordCount + truncated content body.
- 7 existing hand-rolled modals re-wrapped in Radix Dialog; 2 of them
  gained Escape / backdrop-close they previously lacked.
